# دواء تك — Dawa Tech (Patient–Pharmacy Marketplace)

منصة ويب ذكية للربط المباشر بين المرضى والصيدليات المحلية في جمهورية مصر العربية. يرسل المريض وصفته الطبية أو اسم الدواء لتقوم الصيدليات المعتمدة في نطاقه الجغرافي بالرد الحي بتوفر الدواء وسعره الدقيق.

> **ملاحظة معمارية هامة:** لا توجد قاعدة بيانات أدوية مركزية موحدة — الصيدليات هي المصدر الفعلي والحصري للتوفر والأسعار.

---

## 🚀 ما تم إنجازه في المرحلة الأولى (Phase 1 — Foundations)

1. **الهيكل التأسيسي الموحد (Unified Scaffold):**
   - واجهة خلفية مبنية بـ **Python + FastAPI** (Async-first).
   - واجهة أمامية مبنية بـ **React + TypeScript + Vite** بتصميم عربي كامل (**RTL**) وخط **Cairo**.
   - قاعدة بيانات **PostgreSQL 16** مع إدارة الهجرات عبر **Alembic**.
   - دعم كامل للتشغيل عبر **Docker Compose** وكذلك التشغيل المباشر محلياً.

2. **المصادقة والأمان متعدد الأدوار (Multi-Role Authentication & Security):**
   - 3 أدوار رئيسية مع حراسة المسارات: **مريض (`patient`)**، **صيدلية (`pharmacy`)**، **مشرف (`admin`)**.
   - دعم تسجيل الدخول بواسطة **البريد الإلكتروني أو رقم الهاتف المصري**.
   - استراتيجية الرمز المزدوج: **Access Token قصير الأجل (30 دقيقة)** + **Refresh Token طويل الأجل (14 يوماً)** مع تدوير الرمز (Token Rotation) وإلغاء الصلاحية (Revocation) عند الخروج، مع معترض تلقائي (Axios Refresh Interceptor) في الواجهة الأمامية.
   - تحديد معدل الطلبات (**Rate Limiting**) عبر `slowapi` لحماية نقاط تسجيل الدخول والتسجيل ورموز التحقق من هجمات التخمين.

3. **التحقق من رقم الهاتف/البريد برمز التحقق (OTP Verification):**
   - إنشاء الحساب بحالة غير مفعلة (`is_verified = False`).
   - توليد وتخزين هاش رمز التحقق (6 أرقام) بصلاحية 10 دقائق وحد أقصى 5 محاولات.
   - **في بيئة التطوير (Dev Mode):** يُطبع رمز الـ OTP بوضوح في شاشة الطرفية (Terminal/Console) داخل صندوق `[DEV OTP DISPATCH]` لتسهيل الاختبار دون الحاجة لمزود SMS خارجي.
   - **المعالجة السلسة لإعادة التسجيل:** إذا قام مستخدم غير مفعّل بإعادة التسجيل، لا يتم إظهار خطأ تكرار ولا يُنشأ سجل مكرر، بل يُرسل رمز OTP جديد تلقائياً لتمكينه من إكمال التفعيل بسلاسة.

4. **إحداثيات جغرافية دقيقة للمريض والصيدلية (`lat` & `lng`):**
   - أعمدة حقيقية ومفهرسة في جدول المستخدمين والصيدليات لدعم المطابقة الجغرافية ونطاق الـ 5 كم في المرحلة الثانية.
   - زر تحديد الموقع التلقائي عبر الـ GPS في واجهات التسجيل.

5. **تسجيل الصيدليات واعتماد التراخيص (License Verification Queue):**
   - حقل رقم الترخيص الرسمي إلزامي وفريد.
   - تبدأ الصيدلية بحالة `pending` (قيد المراجعة).
   - جدار حماية برمجي (`get_current_verified_pharmacy`) يمنع الصيدليات غير المعتمدة من الوصول لاستقبال الطلبات حتى يتم فحص الترخيص واعتماده من قبل المشرف.
   - لوحة تحكم المشرف تتضمن طابور مراجعة التراخيص مع أزرار **اعتماد** و **رفض مع سبب**، وتدوين كل حركة في سجل التدقيق الأمني (`AuditLog`).

## 🐳 التشغيل عبر Docker Compose (الطريقة الموصى بها)

```bash
# تشغيل جميع الخدمات (Postgres, Redis, Backend, Frontend)
docker compose up --build
```

- **الواجهة الأمامية (Frontend):** [http://localhost:5173](http://localhost:5173)
- **الواجهة الخلفية والتوثيق التفاعلي (Swagger UI):** [http://localhost:8000/api/v1/docs](http://localhost:8000/api/v1/docs)
- **فحص الجاهزية (Health Check):** [http://localhost:8000/health](http://localhost:8000/health)

## 💻 التشغيل المحلي المباشر (Local Host Development)

### 1. تشغيل الواجهة الخلفية (FastAPI Backend)

```powershell
# من مجلد المشروع الرئيسي
cd backend

# تفعيل البيئة الافتراضية
.venv\Scripts\activate

# تشغيل خادم التطوير
uvicorn app.main:app --reload --port 8000
```

### 2. تشغيل الواجهة الأمامية (React Frontend)

```powershell
# من مجلد المشروع الرئيسي
cd frontend

# تثبيت الحزم (إن لم تكن مثبتة)
npm install

# تشغيل خادم التطوير
npm run dev
```

## 🧪 تشغيل الاختبارات الآلية (Pytest Backend Suite)

يحتوي المشروع على 12 اختباراً آلياً شاملاً يغطي كافة متطلبات المرحلة الأولى بنسبة نجاح 100%:

```powershell
# من مجلد المشروع الرئيسي
& 'backend\.venv\Scripts\pytest.exe' backend/tests -v
```

### الاختبارات المغطاة:
1. `test_patient_registration`: تسجيل مريض جديد والتحقق من إحداثيات الموقع وحالة عدم التفعيل حتى إدخال الـ OTP.
2. `test_pharmacy_registration`: تسجيل صيدلية برقم ترخيص مهني وحالة `pending`.
3. `test_duplicate_license_rejection`: منع تكرار رقم ترخيص الصيدلية (400 Bad Request).
4. `test_login_unverified_account_requires_otp`: منع تسجيل الدخول للحسابات غير المفعلة وتوجيهها لـ OTP.
5. `test_login_invalid_password`: التحقق من حماية كلمات المرور الخاطئة (401 Unauthorized).
6. `test_otp_verification_flow`: دورة حياة رمز التحقق (رمز خاطئ، إعادة إرسال، إدخال صحيح، تفعيل الحساب وإصدار الرموز).
7. `test_re_registration_unverified_vs_verified`: معالجة إعادة التسجيل لحساب غير مفعّل (إصدار رمز جديد) مقابل حساب مفعّل (409 Conflict).
8. `test_login_rate_limiting`: التأكد من عمل محدد الطلبات وحظر الهجمات التخمينية (429 Too Many Requests).
9. `test_refresh_token_rotation_and_revocation`: تدوير الرموز ومنع إعادة استخدام الرمز الملغي وإلغاء الجلسة عند الخروج.
10. `test_user_coordinates_persistence`: حفظ وتحديث إحداثيات `lat` و `lng`.
11. `test_pharmacy_verification_and_guard`: جدار الحماية، طابور الاعتماد، واعتماد المشرف مع سجل التدقيق.
12. `test_admin_rejection_flow`: رفض ترخيص صيدلية وتوثيق السبب في سجل التدقيق.
